# Square 0.3.0

Square 0.3.0 聚焦 Canvas 后端的性能与正确性、Win32 Software 呈现交接，以及可快速复现的综合性能测试。共享 UI、CSS、布局、DOM 遍历、编译器与内置 Yoga 以 `origin/main` 的 `ef6409d634349ebafadc29afcf9eeb4dcee0bfed` 为基线，独立合入 Canvas 与软件呈现改动。框架与模板共 22 个 `Wuldas.Square` / `Wuldas.Square.*` 包使用统一版本，仍面向 .NET 10。项目处于实验阶段，公共 API 和模板语法可能继续调整。

## Canvas 后端

- **准备与缓存**：复用路径、渐变与文字准备结果，减少相同逻辑输入的重复构造；资源变化、缓存失效和生命周期仍参与判断，不缓存整个测试画面代替实际绘制。
- **裁剪与图层**：完善路径裁剪、分组透明度、图层合成及资源释放，保留 source-over 的语义边界。功能修正可能改变此前错误的像素，不能一概称为同图纯性能优化。
- **Software**：修正 alpha 表示与混合路径，优化覆盖计算和可用的 SIMD 路径；部分覆盖、透明像素与标量回退保持相应正确性检查。
- **Vulkan**：改进路径、渐变、文字与图集资源复用，使用两帧 swapchain/frame-resource 与 fence 管理在途资源；计数和等待边界单独记录，不把提交、渲染 fence 或 API 返回率称为物理显示完成。
- 原生渐变插值、描边 cap/join、图片采样与 AA 仍有后端差异。局部语义探针通过不代表全帧逐像素一致，也不构成统一 GPU 吞吐排名。

## 单一综合性能入口

Canvas 默认改为一个固定综合场景、一个档位、control-only：六目标各三轮，共 **18 个独立进程**；显式加入原 main 的三个 Square 后端对照时为 **27 个进程**。旧 29 场景、负载梯度和 capture/control 对照仅在显式扩展或诊断路径运行，历史输入与原始证据保留。

综合场景复用四 panel dashboard，并补齐 transform、stroke 与逐帧 paint，覆盖填充、alpha、矢量重用与变化、文字、图片、变换、裁剪、渐变和分组图层。保持 1280×800、DPR1、固定字体/图片/seed、60 逻辑帧预热和 120 测量帧，不为慢框架修改负载以追求 60 FPS。

```powershell
pwsh -File samples/Square.Sample.CanvasBenchmark/Run-Benchmark.ps1 -OutputDirectory artifacts/canvas-comprehensive/run-001
```

依赖与完整说明见 [Canvas 样例](../../samples/Square.Sample.CanvasBenchmark/README.md)。报告保留 `target, CPU, FPS, avgPrivate, avgWS, PublishMiB` 六列、实际 N、范围、失败与质量边界。Canvas CPU 为进程树监控生命周期下界，平均内存按真实相邻采样时间积分；producer FPS 使用测量事件时间戳，不是 inverse caller wall 或 scanout。布局 UI 的 CPU 与约 1Hz 内存均值仍使用原 measurement-window 定义，两组绝对值不直接混比。

布局性能窗口标题新增实际后端和运行模式，例如 `Square CSS animation benchmark-direct2d-aot`。`jit/aot` 由运行时 `RuntimeFeature.IsDynamicCodeSupported` 判断，不靠发布目录名称猜测；Auto 渲染模式、默认窗口样式与原计时、帧数、CPU 和内存逻辑保持。

## Win32 Software 呈现

- 共享 DIB 与 bitmap 在 GDI 完成访问后才交回 CPU 复用；脏区合并为一次拷贝。
- 每次成功、非空的 Software 提交最多等待一次 DWM。空更新和 `WM_PAINT` 不额外等待合成，原 60 Hz 帧截止点推进不变；隐藏、最小化及不可用窗口跳过相应等待，失败不追加忙重试。
- 这是 **best-effort DWM 合成节拍等待**。`S_OK`、窗口 DC 像素正确或约 60 FPS，都不能单独证明硬件原子翻页、物理扫描无撕裂或最终桌面图像正确。
- **已知限制**：本轮严格原生桌面截图门槛仍为 **0/2 通过，保持 limited**。CPU/WindowDC 与桌面捕获的结果不一致，现证据不足以确认最终桌面输出，也不据此直接归因于生产 raster。逐像素透明窗口不因本次调整获得统一呈现或桌面像素正确性保证，仍需按实际宿主验证透明像素、脏区与合成行为。

软件呈现配置、0/2 limited 限制及本轮结果见[测量记录](../benchmarks/2026-11-11.md)。同步修复前27次综合与20次布局对照保留为历史阶段，不用于替代修复后的正式测量。

## 测试与升级

- 同步 Canvas 缓存、alpha、图层与帧资源的回归断言，区分托管正确性、离屏像素、实际窗口、原生桌面截图和需显式开启的 GPU/呈现门槛。未执行或 gated-off 不能记为真实原生验证通过。
- 仓库构建固定使用修补后的 .NET 10 runtime / ILC / ILLink / apphost 10.0.14：SDK 10.0.3xx 默认解析的 10.0.11 受 GHSA-p3jp-9v83-76w9 影响，这里通过显式版本对齐解决，而不是关闭 NuGet 审计或压掉警告。
- 现有应用应将框架、编译器、平台、后端及扩展包统一升级到 0.3.0，不混用内部包版本。使用模板新建的项目同样引用 0.3.0。
- Windows / Win32 与 Linux / X11 仍为主要桌面宿主，macOS 保持桌面 CI；Android 仍为 Experimental，既有 arm64 真机及官方 NativeAOT 边界不变。

```bash
dotnet new install Wuldas.Square.Templates@0.3.0
dotnet new square -n MyApp
dotnet run --project MyApp
```

安装与本地验证见[入门指南](../Getting-Started.md)，历史改动见 [0.2.0 发布说明](0.2.0.md)。发布由 `v0.3.0` 标签对应的工作流构建，校验 22 包及内部依赖版本、验证包使用方，再通过 NuGet Trusted Publishing 发布；手动 workflow_dispatch 只构建验证，不发布。
